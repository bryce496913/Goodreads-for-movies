# V0.7 release notes — integration candidate

**READY PENDING NATIVE TEST EXECUTION — not V0.7 VALIDATED.** Functional descriptions below describe implemented source, not a recorded native pass. Persistent offline artwork remains blocked and is not presented as complete. No TestFlight upload or automatic merge is included.

## Implemented workstream

- **Faster movie logging:** one coordinated Save for an optional watched date, overall personal rating edit and a new viewing-linked private review. Repeat watches use separate events; untouched ratings/reviews remain independent. Cancel and failed saves preserve the draft/data through the existing writer.
- **Viewing Calendar:** month/day navigation alongside the same diary List, multiple same-day watches, explicit undated handling, locale first weekday and stable civil-date/time-zone semantics.
- **Expanded movie/TV discovery:** idle Search Browse, movie/TV switching, weekly Trending, Popular, Top Rated, per-media Genres and provider Similar Titles. Existing typed title Search remains. Manual bounded pagination and cancellation reject stale responses; browsing alone does not create a personal record.
- **Year in Review:** annual/monthly diary activity and distinct titles, current all-time half-star ratings, eligible local genre coverage and explicitly dated TV marking actions. Unknown dates and historical rating values are not invented.
- **Metadata/artwork recovery:** explicit header refresh for incomplete/expired information, clear local-save versus provider error feedback, friendly identity-preserving placeholders, saved-poster lease checks and bounded static-image preflight. Artwork remains memory-only.

Continue Watching/direct episode actions, collections/multiple membership/manual order, local Watchlist discovery, Library search/filter/sort, ratings, reviews and viewing history remain part of the app. Four native tabs and Paper/Ink/Ember are unchanged. No account, social, remote analytics or cloud-sync feature is introduced.

## Data and offline compatibility

V0.7 uses unchanged LibrarySchemaV3 (3.0.0) and retained historical migration definitions. No destructive reset, empty-store fallback or schema rewrite is added. Supported fixture migrations and actual copied historical stores still require Apple execution; unavailable historical shapes are not implicitly supported.

Personal backup export stays **v2**, with **v1/v2** import and explicit Keep Existing merge/conflict handling. Reviews, diary repeats/dates, ratings, episode flags, collection membership/manual order stay personal; provider metadata/artwork/credentials are excluded. Native round-trip, rollback and relaunch results are pending.

Library, private edits, logging, diary/Calendar, collections, local Watchlist discovery and statistics operate from local data. Catalog-dependent progress/genres/title text require still-eligible saved metadata. New provider Search/Browse/Similar/pages/refresh need authorized configuration and network; only current valid in-process results can be reused offline. Artwork can vanish after eviction/termination/relaunch, as its durable-storage rights gate remains **BLOCKED**.

TMDB's 30-day refresh threshold and 150-day maximum/original receipts remain. No new provider is installed and no legal/account authorization is certified. App marketing version/build remains 0.5.0/12; bundle identity/signing defaults are unchanged to avoid an unrequested sandbox/distribution change.
