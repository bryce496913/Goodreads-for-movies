## Persistence and migration — every runtime row UNRUN

Use isolated test stores/dedicated simulators and copies/backups of historical data; never uninstall or reset an actual user installation to make a test pass.

1. Fresh install / empty store: launch all tabs, zeros/unavailable average, no seed records. Normal Release launch must ignore UI fixture arguments. Fail store initialization/read/save deliberately using test injection; verify visible errors/retry and rollback, not disposable fallback data.
2. Populate ratings/favorites/status, multiple reviews, dated/undated/rewatch events, specials and regular watched episodes. Relaunch, background/foreground, force-quit and relaunch offline. Verify UUIDs, exact MediaIDs, timestamps/text/flags and metadata remain stable.
3. Run `StabilizationTests/testPreDashboardSchemaMigratesWithoutLosingExistingRecords`. `Legacy010Schema` reproduces the PR010 library declaration before optional ratingUpdatedAt, alongside the four already-existing models. It writes a real temporary disk store before opening the current schema. This is **not yet a passing migration test** or proof for PR001–009 installs.
4. On copies of actual earlier build stores, test the supported upgrade chain to 0.5.0, with the same App ID/production schema configuration. Verify all fields/entities, including legacy rating/review data and new nil rating timestamps. Record source app version/schema, OS/Xcode, counts before/after and sanitized migration errors. Any unsupported source schema keeps the release blocked; do not add a destructive reset or claim blanket migration safety.
5. Refresh metadata repeatedly, change statuses/ratings/reviews repeatedly, delete just one event, move an episode between seasons, then reopen. Private data and unrelated titles must remain. Invalid/missing remote metadata must not remove content. A failed save must restore the earlier state atomically.
6. Verify Keychain token access while unlocked, after relaunch and removal. Device-only tokens are not synchronized or restored to a different device; explicit removal deauthorizes this local credential. No tests target the real token service. Do not log tokens or private text.

No production schema field or migration plan is changed by 012. Previous optional additions/new entities rely on SwiftData inferred migration; that is an assumption until executed. A reopen with the current schema alone does not prove a historical upgrade.

## Performance/resource observations — runtime measurements unavailable

Static findings: LibraryStore reloads collections on commits; Library projections/sorting are main-actor O(n log n) on source revisions/sort changes and O(n) filtering. Season UI decodes JSON and scans flags repeatedly on redraw; large lists need profiling. Dashboard copies scalar/COW values on main actor and runs grouping/decoding/sorting off actor, cached by revision/day. Detail cache holds at most 20 session snapshots. Images use bounded provider sizes; OS cache eviction is expected. Transport uses ephemeral URLSession with 30-second request/60-second resource timeouts, rejects redirects and has no automatic retry loop. No timing, peak memory or responsiveness result was measured here.
