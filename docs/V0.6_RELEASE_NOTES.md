# V0.6 implementation and stabilization notes

**READY FOR PERSONAL DEVICE VALIDATION — native validation remains outstanding.** This is not V0.6 VALIDATED. TestFlight is deferred and is not required for the V0.6 implementation gate. App version/build and bundle identity are unchanged.

## Implemented through Pass 034

- Continue Watching uses locally reliable next-episode eligibility, separate season navigation and a direct watched action that preserves independent personal status/rating/history.
- Private custom collections support movies/TV, multiple membership, independent manual ordering, offline persistence and personal-only backup/recovery integration.
- What Should I Watch? chooses uniformly from unique Watchlist identities or an explicitly selected collection, using local media/OR-genre/inclusive-year/movie-runtime filters. Missing fields fail required filters; selection never writes personal data.
- V0.6 controls reuse Paper/Ink/Ember tokens, native navigation and shared button/placeholder styles, with explicit collection removal/delete confirmations, accessible reorder alternatives and keyboard dismissal.
- Existing Search, Details, Library, ratings, reviews/diary, TV progress and Home/Profile remain in place.

## Pass 035 stabilization

**P1 fixed at source — managed archive path confinement:** archive conversion previously enumerated/opened/removed files through substituted symbolic links. It now rejects linked roots/directories and linked or nonregular store/journal/output paths before conversion. It preserves the target and reports an unresolved archive, which keeps provider activation blocked rather than ignoring the failure. This is a preflight check in the app's private storage, not a claim of protection against concurrent malicious filesystem replacement.

A second P1 source gap is repaired: archive-only folders now revalidate recovery JSON; corrupt/unsupported/missing archives remain preserved and block provider activation.

Four new linked-path cases, three archive-only revalidation cases, a cross-feature disk reopen/expiry/refresh/export/restore test, a restore-cancellation test, a 500-collection/5,000-membership integrity test and four benchmark methods were added in existing test files. They are **authored, UNRUN**, not runtime evidence. Historical schema definitions remain frozen; no model or migration stage was changed.

Documentation now inventories all eight retained schema shapes and the V3 collection entities, corrects stale claims that manual export/restore does not exist, and provides current validation/checklist commands. The local validation script never uploads, resets data or adds Xcode CI.

## Artwork, metadata and data ownership

Pass 030 persistent artwork licensing remains **BLOCKED**; bounded memory-only artwork and stable placeholders are implemented. Offline relaunch can lose images. No disk artwork cache, rights exemption or guaranteed offline artwork is claimed. Metadata's actual retrieval date controls a strict 150-day maximum and 30-day refresh eligibility; reads/personal edits do not renew it. Provider refresh cannot replace ratings, review text, viewing events, status, favorites or watched flags. Portable backup v2/internal recovery format 2 retain collections/order and personal values, while v1 reading remains supported; provider content and credentials are excluded.
