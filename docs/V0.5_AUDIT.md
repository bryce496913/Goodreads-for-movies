# V0.5 technical audit — pass 012

Scope: 71 production Swift files, 25 unit/UI Swift files (including fixtures), native project/shared scheme, five SwiftData models, provider configuration and existing feature/validation documents. Review is static; compiler warnings, linker failures, SwiftData macro behavior, rendered layouts and runtime performance are unverified. The [test plan](V0.5_TEST_PLAN.md) records evidence and coverage rather than inventing acceptance passes.

## Findings and repairs

- Diary code had five calls to the removed `writeDiary` helper. All now use LibraryStore’s existing transaction/save/rollback path, preserving DiaryError and TVProgressError propagation. This is a source-level build blocker that grammar parsing cannot detect. Existing diary tests and new cross-feature/rollback cases still require execution.
- Search could only obtain a token from an Xcode process environment, which is unavailable to a normally installed TestFlight build. The minimal Settings form now stores an explicitly supplied token in iOS Keychain; Release reads that store, not development environment variables. Search service replacement cancels/restarts the current query and rejects obsolete results. Cached local records are untouched. Already open detail models retain their prior service until reopened.
- Attribution was only text in provider-backed screens. Current FAQ requires an approved logo and About/Credits placement. The unmodified official SVG and notice are now available offline in About & Credits. This does not resolve provider licensing/retention approval.
- Search used a segmented picker at every Dynamic Type size; it now follows Library’s native menu fallback at accessibility sizes. Layout-driven change, no fixed delays/offsets. Real rendering/VoiceOver remains pending.
- A canceled artwork task could report its failure after the provider was replaced. Its error publication now checks cancellation. Generation/cancellation protection for search/pagination/details/TV/dashboard remains in place.
- Version/build/display settings were still 0.1.0/1. Shared base settings now provide 0.5.0/12 and MovieTracker Beta, with ignored local overrides. Placeholder App ID remains the tracked default to preserve earlier sandboxes; this is explicitly not distribution-ready. Unit-test host and test target dependencies remain configured.

No production entity declarations changed in 012; no automatic import/reset, destructive migration or fallback to a disposable database was added. The historical fixture is test-only. Migration support remains a runtime gate. The reusable EmptyStateCard currently has no call sites; this is not a core-function defect and was not removed merely as cleanup. No duplicate writer/service architecture was introduced.

## Durability, navigation and resource assessment

Each tab retains its own NavigationStack. Home/Library/Profile share saved-media destination handling; Search uses the same MediaDetailView and model factory. No second detail/episode architecture was added. Existing Library removal confirmation explicitly describes which personal fields are removed and keeps separate reviews/history/flags. Reviews detach from a deleted event; episode refresh retains stable IDs and watched state. Empty/missing-data paths use visible errors/placeholders, not fake records. These are code-path observations, not successful user-journey runs.

Expensive dashboard aggregation is detached over immutable Sendable input; publishing is revision/day cached and generation guarded. Other main-actor work includes collection reload/sorting, snapshot/episode JSON decoding and image decoding. Repeated season calculations and full reloads on writes should be profiled with the existing 5,000-title and 1,000-watched-episode datasets. No measured stall/leak/launch or memory finding can be established on Linux. Do not claim performance acceptance without Instruments/XCTest evidence.

Release remains **NOT READY — BLOCKERS REMAIN**. Fixes are concrete and reviewable, but all mandatory runtime, migration, provider-retention, signing/icon/privacy and archive gates remain as listed in [KNOWN_ISSUES.md](KNOWN_ISSUES.md).
